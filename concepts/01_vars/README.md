# 01 · 变量、常量与类型推断：写类型是可选的，有类型是必须的

> Go 是静态类型语言，却几乎不用手写类型：编译器的类型推断替你省掉大部分类型标注，常量还另有一套跨类型使用的规则。本篇用一份可运行的 demo 把 `var`、`:=`、常量与 iota 的规则逐条跑成输出，读完你能判断每条声明该用哪种写法、为什么有的赋值合法有的编译错。

## Background

Go 之前的静态类型语言（变量类型在编译期就确定的语言，如 C、Java）要求每个声明写全类型：`int count = 0;`。类型安全有了，书写负担也重了。

动态语言走了另一个极端：声明不写类型，`100` 既能做整数运算也能直接当浮点数用。灵活的代价是类型错误拖到运行时才暴露。

从动态语言转来的人常在两处栽跟头：

- `k := 100` 之后执行 `var f float64 = k` 编译报错——`100` 明明既能当 int 也能当 float64？
- 把 `'A'` 当成字符串，实际它是 `rune`（int32 类型的别名）。

这两个困惑同源：直接写在代码里的数值，有的场合能换着类型用，有的场合一旦定了型就不再通融。本篇要做的事就是把这条边界逐条跑出来。

## What

本篇的主角是类型推断（编译器根据初始值推导变量类型、从而省掉手写类型标注的机制）。推断不等于"没类型"：每个字面量（源码里直接写出的值，如 `100`、`"go"`、`'A'`）在编译期就有默认类型。

心智模型一句话：声明方式（var/`:=`/const）决定"书写自由度"，编译器类型检查是唯一的裁判，字面量的默认类型决定最终落到哪个类型。

可以把声明过程想象成过安检：带什么行李（初始值）就贴什么标签（类型），标签一旦贴上不再更换。但和真实安检不同的是，无类型常量（`const pi = 3.14` 这种不写类型的常量）这件行李在检查前没有固定标签——交给哪个柜台就按哪个类型用。

## When to Use

先说在做什么事的时候选哪种写法：

- 在函数内写逻辑、拿到初值就能用：`:=` 一次完成声明与初始化，函数内最常用。
- 在包级定义不变的配置（超时阈值、容量单位）：`const` + iota 表达枚举与移位单位。
- 在初值尚不确定、或需要零值（只声明未赋值时自动获得的默认值，如 `0`、`false`、`nil`）兜底：`var s []int` 只声明不赋值。

何时不用 `:=`：需要精确控制宽度时写显式类型，例如 `var i int64 = 0`——`i := 0` 会定型为 int，之后再赋给 int64 变量就编译错。

何时不用 const：运行期才能确定的值存不进常量，常量在编译期定值。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| `var a int = 10` | 类型与初值都显式 | 需要精确类型（int64、float32）或包级声明 |
| `a := 10` | 函数内的简写形式 | 函数内绝大多数声明 |
| `const a = 10` | 编译期定值、可跨类型使用 | 常数、枚举、配置常量 |
| `var a int` | 只声明不赋值 | 初值未知或依赖零值语义 |

## How It Works

### 三种声明形态的边界

`var` 到处可用、可以只声明不赋值（零值兜底：`0`/`""`/`false`/`nil`）；`:=` 是函数内的语法糖（同一语义的简写，编译后与完整写法等价），必须立刻初始化，且左边至少有一个新变量。包级变量只能用 `var`。

你在输出第 1 段看到的 `c 零值 = true`，验证的就是 `var c bool` 只声明不赋值、由零值兜底这一行为。

### 字面量的默认类型

`100` 推断为 `int`（不是 int64）、`1.5` 推断为 `float64`（没有 float32 推断）、`'A'` 是 `rune`（int32 别名）。默认类型在 `:=` 的瞬间就定型了，之后类型不再通融——这就是 `k := 100; var f float64 = k` 编译错的原因。

输出第 2 段的 `h 是 rune(int32): true` 与 `i 是 byte(uint8): true`，验证的就是字符与字节两类字面量各自落到的默认类型。

### 无类型常量的"延迟定型"

`const pi = 3.14159` 没有固定类型，它是一个编译期常量表达式：赋给 `float64` 就按 float64 用，参与整数运算时能当无类型整数用（`const maxInt int = 1 << 31` 则始终是 int）。同一个无类型常量能跨类型使用，变量做不到——这是常量与变量最本质的差别。

输出第 3 段 `pi 赋给 float64: true | maxInt/2 = 1073741824`：前者是 pi 跨类型赋值成功，后者是显式 int 常量的移位除法结果。

### iota：唯一的枚举姿势

iota（const 块内按行递增的计数器）在每个 `const` 块从 0 开始逐行 +1；省略表达式即重复上一行（`Sunday/Monday/Tuesday`），配合表达式就是 `KB/MB/GB` 的移位枚举。

输出第 4 段 `Sunday=0 Monday=1 Tuesday=2: true` 与 `KB=1 MB=1024 GB=1048576: true` 分别对应"省略表达式重复"与"逐行移位"两种用法。

### 关键语法速查

| 语法 | 含义 | 为什么重要 |
|---|---|---|
| `var a int` | 显式声明，零值兜底 | 包级变量唯一选择 |
| `d := true` | 短声明 + 推断 | 函数内最常用，但必须初始化 |
| `'A'` | rune（int32 别名） | 不是 string；字符串遍历得到的就是它 |
| `const pi = 3.14` | 无类型常量 | 类型延迟定型，可跨类型赋值 |
| `1 << (10*iota)` | iota 表达式 | 省略表达式即逐行重复 |

## Pitfalls & Q&A

踩坑清单（每条按"现象 → 原因 → 解法"展开）：

- 现象：`k := 100` 后写 `var f float64 = k` 编译错。原因：`k` 已定型为 int，变量不可跨类型赋值。解法：写 `var f float64 = 100`，让无类型常量 `100` 在赋值瞬间定型为 float64。
- 现象：`'A'` 与 `"A"` 混用导致类型不匹配。原因：前者是 int32 的 rune，后者是 string。解法：需要单字符用 rune，需要文本用双引号字符串。
- `byte` 是 `uint8` 的别名、`rune` 是 `int32` 的别名——`%T` 打印出来是别名指向的类型。
- 未使用的局部变量是编译错（不是警告），演示代码里的每个变量都要"被用掉"。

深入问答：

**Q：`:=` 和 `var` 除了位置还有什么区别？**
A：`:=` 要求左侧至少一个新变量（可部分复用：`a, err := f()` 到 `b, err := g()` 是复用 err）；`var` 支持声明与初始化分离和包级作用域。

**Q：为什么无类型常量能"既是 int 又是 float64"？**
A：它本质是任意精度的编译期数值，不占运行时存储；每次使用时按上下文定型。变量则在声明时定型，之后不可跨类型赋值。

**Q：rune 和 byte 什么时候用哪个？**
A：`[]byte` 面向原始字节（IO、编码），`[]rune` 面向字符（按字符切分/统计）。`len("中")` 是 3（字节），`len([]rune("中"))` 才是 1（字符）。

**Q：iota 跳行还连续吗？**
A：iota 按 const 块内的行号计数，与是否省略表达式无关；中间插入新 const 声明会占一行，注释与空行不占。
