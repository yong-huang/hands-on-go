# 01 · 变量、常量与类型推断：写类型是可选的，有类型是必须的

> Go 是静态类型语言，却几乎不用手写类型——编译器的类型推断把声明写得很轻。但"写得轻"不等于"没类型"：字面量在编译期就定下默认类型，无类型常量还有一套独有的"延迟定型"规则。本实验用一份可运行的 demo 把 `var`、`:=`、常量与 iota 的规则逐条跑给你看。

## 1. 为什么需要它

从动态语言转来的人常在两处栽跟头：`k := 100` 之后把 `k` 赋给 `float64` 编译报错（100 明明"既能当 int 也能当 float64"？）；`'A'` 想当然当成字符串，实际是 `rune`（int32）。这些困惑的根源是**字面量默认类型**与**无类型常量**两套规则的边界。本实验把边界跑出来：每条规则都对应一行可验证的输出，注释里还有两行"取消注释就编译错"的陷阱代码。

## 4. 核心概念

### 4.1 三种声明形态的边界

`var` 到处可用、可以只声明不赋值（零值兜底：`0`/`""`/`false`/`nil`）；`:=` 是函数内的语法糖，必须立刻初始化，且左边至少有一个新变量。包级变量只能用 `var`。

### 4.2 字面量的默认类型

`100` 推断为 `int`（不是 int64）、`1.5` 推断为 `float64`（没有 float32 推断）、`'A'` 是 `rune`（int32 别名）。默认类型在 `:=` 的瞬间就定型了，之后类型不再通融——这就是 `k := 100; var f float64 = k` 编译错的原因。

### 4.3 无类型常量的"延迟定型"

`const pi = 3.14159` 没有固定类型，它是一个**编译期常量表达式**：赋给 `float64` 就按 float64 用，参与整数运算时能当无类型整数用（`const maxInt int = 1 << 31` 则始终是 int）。同一个无类型常量能跨类型使用，变量做不到——这是常量与变量最本质的差别。

### 4.4 iota：唯一的枚举姿势

`iota` 在每个 `const` 块从 0 开始逐行 +1；省略表达式即重复上一行（`Sunday/Monday/Tuesday`），配合表达式就是 `KB/MB/GB` 的移位枚举。

## 5. 关键字段与坑清单

| 语法 | 含义 | 为什么重要 |
|---|---|---|
| `var a int` | 显式声明，零值兜底 | 包级变量唯一选择 |
| `d := true` | 短声明 + 推断 | 函数内最常用，但必须初始化 |
| `'A'` | rune（int32 别名） | 不是 string；字符串遍历得到的就是它 |
| `const pi = 3.14` | 无类型常量 | 类型延迟定型，可跨类型赋值 |
| `1 << (10*iota)` | iota 表达式 | 省略表达式即逐行重复 |

坑清单：

- `k := 100` 已定型为 int：`var f float64 = k` 编译错，而无类型常量 `100` 可以——差别在"定型时机"
- `'A'` 与 `"A"` 完全不同：前者是 int32 的 rune，后者是 string
- `byte` 是 `uint8` 的别名、`rune` 是 `int32` 的别名——`%T` 打印出来是别名指向的类型
- 未使用的局部变量是编译错（不是警告），演示代码里的每个变量都要"被用掉"

## 7. 深入要点

**Q：`:=` 和 `var` 除了位置还有什么区别？**
A：`:=` 要求左侧至少一个新变量（可部分复用：`a, err := f()` 到 `b, err := g()` 是复用 err）；`var` 支持声明与初始化分离和包级作用域。

**Q：为什么无类型常量能"既是 int 又是 float64"？**
A：它本质是任意精度的编译期数值，不占运行时存储；每次使用时按上下文定型。变量则在声明时定型，之后不可跨类型赋值。

**Q：rune 和 byte 什么时候用哪个？**
A：`[]byte` 面向原始字节（IO、编码），`[]rune` 面向字符（按字符切分/统计）。`len("中")` 是 3（字节），`len([]rune("中"))` 才是 1（字符）。

**Q：iota 跳行还连续吗？**
A：iota 按 const 块内的**行号**计数，与是否省略表达式无关；中间插入新 const 声明会占一行，注释与空行不占。
