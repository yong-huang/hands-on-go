# 05 · 结构体、方法与接口：Shape 一次遍历，两种实现

> struct 把数据组织在一起，方法给数据挂上行为，接口只认行为不认类型。没有接口，"对所有图形求面积"就要为每种图形写一个分支；有了接口，一个 `[]Shape` 循环遍历所有实现——而类型甚至不需要声明"我实现了这个接口"。本实验用一份可运行的 demo 把值/指针接收者、隐式实现与多态逐条跑给你看。

## 1. 为什么需要它

初学者常在三处困惑：`r.Scale(2)` 能编译，但把 `r` 赋给接口后"方法不见了"；`var s Shape = c` 之前没人写过 `implements Shape`，编译器怎么知道 Circle 实现了 Shape；接口变量里到底装了什么。根源是两条规则的边界：**方法集**（值类型与指针类型各自拥有哪些方法）与**隐式实现**（接口满足由方法集决定，与声明无关）。本实验把边界跑出来：每条规则都对应一行可验证的输出。

## 4. 核心概念

### 4.1 struct 与方法：接收者就是"第一个参数"

`func (c Circle) Area() float64` 本质上等价于 `func Area(c Circle) float64`——接收者是函数签名的一部分。值接收者拿到**副本**，方法内改字段不影响原值；要修改调用者手里的数据，用指针接收者（见 `Scale`）。

### 4.2 接口的隐式实现

`Shape` 只声明三个方法签名；`Circle`、`Rectangle` 从未写过任何 "implements"。只要一个类型的方法集覆盖接口的全部方法，它就满足该接口——赋值 `var s Shape = c` 编译通过即是证明。定义（接口方）与使用（实现方）完全解耦：你可以给第三方库的类型"补"出接口实现。

### 4.3 方法集：值类型 vs 指针类型

规则一句话：**值类型 `T` 的方法集只含值接收者方法；`*T` 的方法集含两者**。所以 `Rectangle` 值可以直接赋给 `Shape`（Area/Perimeter 是值接收者），但接口变量调不到 `Scale`——它属于 `*Rectangle` 的方法集。而普通值变量 `r.Scale(2)` 能编译，是因为 `r` 可寻址，编译器自动改写成 `(&r).Scale(2)`；这个语法糖在接口里不生效。

### 4.4 接口切片多态遍历

`[]Shape` 里的元素可以混装不同具体类型，`for` 循环里同一个 `sh.Area()` 调用按**动态类型**分派到各自的实现。新增三角形时循环一行不改——这是"对扩展开放"的最小形态。

## 5. 关键字段与坑清单

| 语法 | 含义 | 为什么重要 |
|---|---|---|
| `func (c Circle) Area()` | 值接收者，操作副本 | 只读方法首选；T 的方法集含它 |
| `func (r *Rectangle) Scale()` | 指针接收者，可改原值 | 需要修改状态时必须用它 |
| `var s Shape = c` | 隐式实现 + 装箱 | 无 implements 声明，编译器检查方法集 |
| `[]Shape{c, Rectangle{...}}` | 接口切片混装 | 同一循环多态分派 |
| `%T` 打印 `main.Circle` | 接口的动态类型 | 接口 = (动态类型, 动态值) 二元组 |

坑清单：

- 混用接收者类型是坏味道：同一个类型上值/指针接收者并存（本实验的 Rectangle 是**为演示**才这么写），实际代码应统一——有指针接收者就全用指针
- `var s Shape = r`（值）后调 `s.Scale(2)` 编译错：值类型的接口方法集不含 `*Rectangle` 方法；改成 `&r` 赋值即可
- 给 `T` 定义了值接收者方法，`*T` 自动也拥有（方法集是单向包含：*T ⊇ T）
- 接口变量为 nil ≠ 里面装的指针为 nil——接口是 (类型, 值) 二元组，装了 `(*T)(nil)` 的接口不等于 nil（深入见下一篇断言实验）

## 7. 深入要点

**Q：为什么 Go 不用 implements 声明，靠隐式实现不会更难排查吗？**
A：编译器在赋值点就报错并指出缺哪个方法（"does not implement Shape (missing Perimeter method)"），排查成本不比显式声明高。换来的是解耦：接口使用方按需定义，类型提供方无需预知，也给已有类型（含第三方类型）留了"事后满足接口"的空间。

**Q：值接收者和指针接收者到底怎么选？**
A：默认值接收者；需要修改字段、或结构体较大且拷贝开销敏感、或含 sync 互斥量等不可拷贝字段时用指针接收者。关键是一致性——同一类型混用两种接收者会让方法集规则变得难以推理。

**Q：接口变量在内存里长什么样？**
A：一个两字结构（iface）：指向类型元数据的指针（含方法表）+ 指向数据的指针。`%T` 打印的是前半部分；这也是"动态类型"一词的来源。多态调用的分派走方法表，是运行时的一次间接寻址。

**Q：空接口 `interface{}`（`any`）和 Shape 这类接口差别在哪？**
A：`any` 方法集为空，所有类型都满足它——它放弃类型信息换取"什么都装"，取回数据要靠类型断言。Shape 这类小接口则保留行为契约，调用方可以直接 `sh.Area()`。惯例是接口越小越好（标准库的 io.Reader 只有一个方法）。

## 8. 总结

struct 定义数据，方法挂上行为，接口按方法集隐式匹配——三条规则组合出 Go 的多态：一个 `[]Shape` 循环遍历所有实现，新增图形零改动。把 §3 输出与 §4.3 的方法集规则逐条对照跑一遍，值/指针接收者的边界就再也不用背了。
