# 03 · 数组、切片与 map：定长值类型、动态引用与键值容器

> Go 的容器分三副面孔：数组是定长的**值**，赋值即整体拷贝；切片是**引用**，背后挂着一块可伸缩的底层数组；map 是键值容器，键不存在不报错、返回零值。分不清"值拷贝"与"共享底层"，就会出现"改了 A，B 也变了"或"append 之后看不到新元素"的困惑。本实验用一份可运行的 demo 把三种容器的语义逐条跑出来，验收载体是一个单词频率统计器。

## 1. 为什么需要它

从动态语言转来的人常在三处栽跟头：`b := a`（a 是切片）之后改 `b[0]`，`a[0]` 莫名也变了；`append` 之后把结果赋给一个新变量，旧切片却"丢"了新元素；取 map 里不存在的键不报错，拿到一个零值却以为"存在"。这些困惑的根源是**值语义 vs 引用语义**与 **len/cap 双轨制**。本实验把边界跑出来：每条规则都对应一行可验证的输出，最后一个词频统计器把切片与 map 串成完整的数据流。

## 4. 核心概念

### 4.1 数组：定长的值类型

`[3]int` 的长度是类型的一部分，`[3]int` 和 `[4]int` 是两种不同类型。数组变量装的是**全部元素**：`b := a` 复制整个数组，改 `b` 完全不影响 `a`——`&a[0] == &b[0]` 为 false。长度必须编译期常量，实际工程中数组多作为底层数据结构出现，日常直接用它写业务代码的场景很少。

### 4.2 切片：动态的引用头

切片变量只存三个字段：指向底层数组的指针、`len`（可用长度）、`cap`（底层数组容量）。所以 `b := a` 只复制"头"，两个变量共享同一块底层数组——改一个，另一个看得见。`make([]int, 3, 5)` 显式指定 len=3、cap=5；字面量 `[]int{1,2,3}` 则 len==cap==3。

### 4.3 append 与扩容

`append` 在 `len < cap` 时原地追加、返回原切片头；`len == cap` 时分配一块更大的底层数组（小切片近似翻倍），把旧元素搬过去再追加。**搬家之后旧切片还指着旧数组**——所以必须接住返回值 `s = append(s, x)`，否则"看不到新元素"。

### 4.4 map：无序的键值容器

`m[k] = v` 一套语法兼任增与改；`delete(m, k)` 删键，键不存在也安全；`m[k]` 读不存在的键**不报错**、返回值类型的零值，因此判存在必须用逗号 ok 惯用法 `v, ok := m[k]`。map 遍历顺序故意随机化，需要稳定输出就得自己排序键（见验收程序 §5）。

## 5. 关键字段与坑清单

| 语法 | 含义 | 为什么重要 |
|---|---|---|
| `var arr [3]int` | 定长数组，零值 `[0 0 0]` | 值类型：赋值/传参都整体拷贝 |
| `make([]int, 3, 5)` | len=3 cap=5 的切片 | 预留容量可减少扩容次数 |
| `s = append(s, x)` | 追加并接住返回值 | 可能换底层数组，不接住就丢 |
| `counts[w]++` | 键不存在先得零值再 +1 | 词频统计的惯用一行 |
| `v, ok := m[k]` | 逗号 ok 判存在 | 区分"值为零值"与"键不存在" |

坑清单：

- 数组赋值是拷贝：`copyArr := arr; copyArr[0] = 99` 后 `arr[0]` 不变——数组是值
- 切片赋值是引用：`alias := s; alias[0] = 100` 后 `s[0]` 也变——共享底层数组
- `append` 换底层数组后，旧切片与新切片彻底分家；没换之前共享，"分家时机"最容易误判
- `m[k]` 不存在返回零值不报错：`if m[k] > 0` 会把"不存在"和"值为 0"混为一谈
- map 遍历无序：每次运行的键序可能不同，要稳定输出先 `sort` 键

## 7. 深入要点

**Q：为什么数组设计成值类型，而切片是引用？**
A：数组是"一块连续内存 + 编译期已知长度"，整体拷贝语义让数组可以安全地按值传参、作为 map 键或结构体字段而不被外部篡改。切片把"可变长"外包给底层数组，自身退化为一个三字段引用头，拷贝头（24 字节量级）远比拷贝数据便宜——这是"灵活"与"可控"的分工。

**Q：append 扩容为什么必须接返回值？**
A：`append` 可能返回指向**新数组**的切片头（cap 不够时）。函数参数传值决定了函数内的追加结果必须通过返回值带回；写成 `append(s, x)` 而不接收，等于丢掉了可能已搬家的结果。

**Q：len 和 cap 各管什么？**
A：`len` 是"现在能用几格"，`cap` 是"底层数组总共几格"。越界按 len 判（`s[len(s)]` panic），扩容按 cap 判；`s[:cap(s)]` 能看到预留区。打印 `len/cap` 的变化是观察扩容最直接的方式。

**Q：为什么 map 键不存在不报错？**
A：设计取向是让"统计/聚合"一行写完：`counts[w]++` 依赖"不存在得零值"这一规则。代价是读操作无法区分"值为零值"与"键不存在"，所以语言内建了逗号 ok 惯用法补回这层信息。

**Q：为什么 map 遍历是随机的？**
A：Go 故意在遍历起点上做随机化，防止开发者依赖未定义的遍历顺序写出脆弱代码。需要顺序，就显式收集键并排序。

## 8. 总结

数组用"定长 + 值拷贝"换可控，切片用"引用头 + cap 双轨"换灵活，map 用"零值默认 + 无序"换简洁——三种容器各自的语义边界就是各自的坑位。把 §3 的输出逐行对照 §5 的坑清单跑一遍，再亲手改一下验收文本看词频变化，这组规则就长在手里了。
