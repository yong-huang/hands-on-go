# 03 · 数组、切片与 map：定长值类型、动态引用与键值容器

> Go 的容器分三副面孔：数组是定长的值，赋值即整体拷贝；切片是引用，背后挂着一块可伸缩的底层数组；map 是键值容器，键不存在不报错、返回零值。本篇用一份可运行的 demo 把三种容器的语义逐条跑出来，并以一个单词频率统计器收尾，读完你能解释"改了 A 为什么 B 也变了"、"append 之后为什么看不到新元素"。

## Background

从动态语言转来的人常在三处栽跟头：

- `b := a`（a 是切片）之后改 `b[0]`，`a[0]` 莫名也变了。
- `append` 之后把结果赋给一个新变量，旧切片却"丢"了新元素。
- 取 map 里不存在的键不报错，拿到一个零值却以为"存在"。

这些困惑不是三件孤立的事。在 Python 里列表赋值就是共享、字典取键抛异常，程序员靠语言的单一副面孔形成习惯；Go 把"定长数据"与"可变长数据"拆成两套语义，又让 map 用零值兜底，三套规则各有边界。

分不清"值拷贝"与"共享底层"，就会出现上面三类事故。本篇把三套语义逐条跑出来，最后一个词频统计器把切片与 map 串成完整数据流。

## What

一句话定义：数组是定长的值类型（长度写进类型、赋值整体拷贝）；切片是动态的引用头（自身只存指针和长度信息、共享底层数组）；map 是无序键值容器（键不存在时返回值类型的零值）。

心智模型一句话：数组是值（len==cap 固定），切片是引用头（指针+len+cap，len≤cap 可伸缩），map 是无序键值（`v, ok := m[k]` 判存在）。

可以把切片想象成一张"取件凭证"：凭证上写着仓库地址、可用格子数、仓库总格子数。但和凭证不同的是，`b := a` 复制的是凭证本身，两个凭证指向同一间仓库——改一间仓库，两张凭证都能看见；而扩容是"整仓搬到新址"，只有接住新凭证的人找得到新仓。

## When to Use

先说在做什么事的时候用哪个容器：

- 在做词频统计、分组聚合：切片收集条目 + `counts[w]++` 累计次数，一行动作依赖"不存在得零值"。
- 在按批次处理数据、长度会增长：`make([]int, 0, n)` 预留容量 + `append` 追加，减少搬家次数。
- 在需要编译期定长的底层结构（如固定大小缓冲、矩阵行）：数组按值传递、作为 map 键都安全。

何时不用数组：日常业务代码几乎不直接用 `[3]int`，长度一变就是另一种类型，灵活性差；它多作为底层结构出现。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| 数组 `[3]int` | 长度属于类型，赋值整体拷贝 | 编译期定长、需要值语义（作 map 键等） |
| 切片 `[]int` | 引用头 + 底层数组可伸缩 | 绝大多数序列场景 |
| map `map[K]V` | 无序键值、零值兜底 | 计数、索引、按 key 查找 |

## How It Works

### 数组：定长的值类型

`[3]int` 的长度是类型的一部分，`[3]int` 和 `[4]int` 是两种不同类型。数组变量装的是全部元素：`b := a` 复制整个数组，改 `b` 完全不影响 `a`——`&a[0] == &b[0]` 为 false。

长度必须编译期常量，实际工程中数组多作为底层数据结构出现，日常直接用它写业务代码的场景很少。

输出第 1 段的 `copyArr = [99 0 3] | 修改副本后 arr[0] 仍是 1` 与 `&arr[0] == &copyArr[0] ? false`，验证的就是整体拷贝语义。

### 切片：动态的引用头

切片变量只存三个字段：指向底层数组的指针、`len`（可用长度）、`cap`（底层数组容量）。所以 `b := a` 只复制"头"，两个变量共享同一块底层数组——改一个，另一个看得见。

`make([]int, 3, 5)` 显式指定 len=3、cap=5；字面量 `[]int{1,2,3}` 则 len==cap==3。

输出第 2 段的 `alias=[100 2 3] | 同底层数组: true`：`alias[0] = 100` 的修改透过共享底层数组反映到了 `s` 上。

### append 与扩容

`append` 在 `len < cap` 时原地追加、返回原切片头；`len == cap` 时分配一块更大的底层数组（小切片近似翻倍），把旧元素搬过去再追加。搬家之后旧切片还指着旧数组——所以必须接住返回值 `s = append(s, x)`，否则"看不到新元素"。

输出第 3 段 `append 4 -> len=4 cap=6 (扩容：底层数组搬家)`：cap 从 5 不够用到翻为 6，就是一次搬家；`append 6 -> len=6 cap=6 (恰好满)` 说明下次再追加又要搬家。

### map：无序的键值容器

`m[k] = v` 一套语法兼任增与改；`delete(m, k)` 删键，键不存在也安全；`m[k]` 读不存在的键不报错、返回值类型的零值，因此判存在必须用逗号 ok 惯用法（`v, ok := m[k]`，第二个返回值报告键是否存在）。

map 遍历顺序故意随机化，需要稳定输出就得自己排序键（demo 的词频输出就是这么做的）。

输出第 4 段 `delete 后 ages[bob] ok=false | len(ages)=1`：delete 生效，且逗号 ok 把"键不存在"明确报告了出来。

### 词频统计：切片与 map 的数据流

数据流是：切词（字符串拆成切片）→ `counts[w]++`（map 累计）→ 排序键（切片）→ 输出。`counts[w]++` 之所以成立，依赖"键不存在先得零值再 +1"这条规则。

### 关键语法速查

| 语法 | 含义 | 为什么重要 |
|---|---|---|
| `var arr [3]int` | 定长数组，零值 `[0 0 0]` | 值类型：赋值/传参都整体拷贝 |
| `make([]int, 3, 5)` | len=3 cap=5 的切片 | 预留容量可减少扩容次数 |
| `s = append(s, x)` | 追加并接住返回值 | 可能换底层数组，不接住就丢 |
| `counts[w]++` | 键不存在先得零值再 +1 | 词频统计的惯用一行 |
| `v, ok := m[k]` | 逗号 ok 判存在 | 区分"值为零值"与"键不存在" |

## Pitfalls & Q&A

踩坑清单（每条按"现象 → 原因 → 解法"展开）：

- 现象：`copyArr := arr; copyArr[0] = 99` 后 `arr[0]` 不变。原因：数组是值，赋值即整体拷贝。解法：要共享就改用切片或传指针。
- 现象：`alias := s; alias[0] = 100` 后 `s[0]` 也变。原因：切片赋值是引用拷贝，两者共享底层数组。解法：需要独立副本用 `copy()` 或 `append([]T(nil), s...)`。
- 现象：append 后旧切片"丢"了新元素。原因：`append` 换底层数组后，旧切片与新切片彻底分家；没换之前共享，"分家时机"最容易误判。解法：始终写 `s = append(s, x)` 接住返回值。
- 现象：`if m[k] > 0` 把"不存在"和"值为 0"混为一谈。原因：`m[k]` 不存在返回零值且不报错。解法：用 `v, ok := m[k]` 判存在。
- 现象：map 遍历顺序每次运行不同。原因：遍历起点被运行时故意随机化。解法：显式收集键并 `sort` 后再遍历。

深入问答：

**Q：为什么数组设计成值类型，而切片是引用？**
A：数组是"一块连续内存 + 编译期已知长度"，整体拷贝语义让数组可以安全地按值传参、作为 map 键或结构体字段而不被外部篡改。切片把"可变长"外包给底层数组，自身退化为一个三字段引用头，拷贝头（24 字节量级）远比拷贝数据便宜——这是"灵活"与"可控"的分工。

**Q：append 扩容为什么必须接返回值？**
A：`append` 可能返回指向新数组的切片头（cap 不够时）。函数参数传值决定了函数内的追加结果必须通过返回值带回；写成 `append(s, x)` 而不接收，等于丢掉了可能已搬家的结果。

**Q：len 和 cap 各管什么？**
A：`len` 是"现在能用几格"，`cap` 是"底层数组总共几格"。越界按 len 判（`s[len(s)]` panic），扩容按 cap 判；`s[:cap(s)]` 能看到预留区。打印 `len/cap` 的变化是观察扩容最直接的方式。

**Q：为什么 map 键不存在不报错？**
A：设计取向是让"统计/聚合"一行写完：`counts[w]++` 依赖"不存在得零值"这一规则。代价是读操作无法区分"值为零值"与"键不存在"，所以语言内建了逗号 ok 惯用法补回这层信息。

**Q：为什么 map 遍历是随机的？**
A：Go 故意在遍历起点上做随机化，防止开发者依赖未定义的遍历顺序写出脆弱代码。需要顺序，就显式收集键并排序。
