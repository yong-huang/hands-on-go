# 02 · 流程控制：一条 for 走天下，if/switch 自带初始化语句

> Go 只保留一种循环关键字 `for`，但省略不同部分就能写出全部循环形态；作为交换，`if` 和 `switch` 获得了别家没有的能力——自带一条初始化语句，把变量作用域压到最小。本篇用一个经典练手题 FizzBuzz 把 for 三形态、无表达式 switch、带初始化的 if/switch 全部跑一遍，每条规则都对应一行可验证的输出。

## Background

C 系语言给了三套循环语法：`for`、`while`、`do-while`。写的人要记三套规则，还要在它们之间做选择；而多分支判定用 if-else 链表达时，分支一多、嵌套就深。

另一个常见痛点是临时变量泄漏：为了写一个条件判断，先在函数体里声明 `int r = i % 3;`，这个 `r` 在之后的 50 行里都可见，读代码的人无法确定它还会不会被改。

从其他语言转来 Go 的人常在两处不适应：

- 找不到 `while` 关键字（其实是 `for n <= 15 {}`）。
- `i % 15 == 0` 的判断放在 `i % 3 == 0` 之后，FizzBuzz 永远出不来。

这里的 FizzBuzz 指：遍历 1..15，3 的倍数输出 Fizz、5 的倍数输出 Buzz、公倍数输出 FizzBuzz，其余原样输出。

这两个困惑同源：Go 把循环收敛成一个关键字的三种形态，把多分支判定收敛成自上而下短路的一条链。本篇用 FizzBuzz 把这套规则逐条跑出来。

## What

Go 流程控制的核心组合是：`for` 一个循环关键字通过省略不同部分得到三种形态；`if`/`switch` 可在条件前执行一条初始化语句，变量仅在分支内可见。

心智模型一句话：for 负责把 1..15 逐个送进判定，switch 负责自上而下取第一个为 true 的 case（switch 中的单个分支条件）——`i%15` 必须排在最前，因为 15 的倍数也满足 `i%3==0`，命中即返回、不会落到后面的分支。

可以把无表达式 switch 想象成一道道闸门从上到下排开，每轮的 `i` 像水流过第一道开着的闸门就离开队列。但和一排闸门不同的是，后面的闸门不是"关着的"，而是根本没有被检查——命中即短路。

## When to Use

先说在做什么事的时候选哪种写法：

- 在遍历切片、需要下标和元素一起拿：`for i, s := range xs`，一次到位。
- 在写"多条件优先级判定"（输出替换规则、错误分级）时：无表达式 switch，把最特殊的条件放最前。
- 在条件判断需要一个中间值（取模结果、函数返回值）时：`if r := f(); r == 0`，把 `r` 锁在分支内。

何时不用 switch：只有一两个条件、或条件之间没有并列关系时，if 更自然。

同类方案对比：

| 方案 | 差异 | 什么时候选它 |
|---|---|---|
| `for i := 1; i <= 15; i++` | init/cond/post 三段齐全 | 已知次数的计数循环 |
| `for n <= 15 {}` | 只留条件，分号全省 | 条件驱动的循环（while 语义） |
| `for i, s := range xs` | 下标 + 元素一起拿 | 遍历切片、map、字符串 |
| 无表达式 switch | 自上而下取首个 true，命中即短路 | 同一主题的优先级判定 |
| if-else 链 | 条件之间可以不并列 | 一两个条件的简单判断 |

## How It Works

### for 的三种形态

Go 只有 `for` 一个循环关键字，省略不同部分就得到三种形态：三段式 `for i := 1; i <= 15; i++`（init; cond; post）；while 式 `for n <= 15 {}`（只留条件，分号全省）。

for range `for i, s := range results`（遍历切片，i 是下标、s 是元素）。省略 cond 的 `for {}` 就是死循环，配合 `break` 使用。

你在输出第 2 段看到的 `while 式循环数出 Fizz 的个数 = 5` 与 `results[4]=Buzz`，分别来自 while 式与 range 式两种形态。

### 无表达式 switch：if-else 链的整洁写法

`switch { case n%15 == 0: ... }` 不带表达式时，每个 case 是一个布尔表达式，自上而下取第一个为 true 的分支，后面的全部短路。它和 if-else 链语义等价，但把"判定什么"和"命中做什么"排版对齐，FizzBuzz 这种判定树一眼可读。

输出第 1 段的 `... 14 FizzBuzz`：15 同时是 3 和 5 的倍数，因为 `i%15==0` 排在最前，才没有被 `%3` 分支截走。

### if / switch 带初始化语句

`if r := i % 3; r == 0` 在条件前先执行一条语句，变量 `r` 只在 if/else 作用域内可见——出了这个 if 就是编译错。`switch m := n % 5; { ... }` 同理。这是 Go 的惯用法：把变量的生命周期压到恰好够用的最小范围。

输出第 3 段 `i=3: r==0 → Fizz（r 只在这个 if/else 里可见）`，括号里的说明验证的就是这条作用域规则；第 4 段的 `m=2` 则来自 switch 形态的初始化语句。

### case 默认不穿透

Go 的 case 命中后自动 break，不会落到下一支；要穿透必须显式写 `fallthrough`（且 fallthrough 会无条件进入紧邻的下一个 case，不看它的条件）。输出第 4 段 `n=7: 普通数（m=2 未命中任何分支）` 说明不匹配时不执行任何 case、直接走出 switch。

### 关键语法速查

| 语法 | 含义 | 为什么重要 |
|---|---|---|
| `for i := 1; i <= 15; i++` | 三段式循环 | Go 唯一的循环关键字的第一形态 |
| `for n <= 15` | while 式 | 前后两段全省，分号也不用写 |
| `for i, s := range xs` | range 遍历 | 下标 + 元素一起拿；只要下标写 `for i := range` |
| `switch { case cond: }` | 无表达式 switch | 自上而下取首个 true，等价 if-else 链 |
| `if r := f(); r == 0` | 带初始化语句 | r 仅 if/else 内可见，作用域最小化 |

## Pitfalls & Q&A

踩坑清单（每条按"现象 → 原因 → 解法"展开）：

- 现象：输出里 15 的位置打印了 Fizz 而不是 FizzBuzz。原因：`i%15==0` 没有排在 `i%3==0`、`i%5==0` 之前，15 先被 `%3` 命中。解法：把最特殊的条件放最前，利用命中即短路的性质。
- 现象：无表达式 switch 里写 `case n % 3`（不带比较）编译错。原因：这种形态的 case 是布尔表达式，不是按值匹配。解法：写完整比较 `case n % 3 == 0:`。
- 现象：`if r := i % 3; r == 0` 的 `r` 在 if 块外引用直接编译错。原因：`r` 的作用域仅限 if/else，这是编译错而非警告。解法：需要在外面用就提前用 `var`/`:=` 声明。
- case 默认不穿透；`fallthrough` 无条件进下一支，哪怕它的条件为 false。
- 未使用的循环变量是编译错（不是警告），演示代码里每个变量都要"被用掉"。

深入问答：

**Q：为什么 Go 砍掉 while 和 do-while 只留 for？**
A：三段式的 init/cond/post 本来就都可以省，`for n <= 15 {}` 与 while 完全等价，`for {}` 就是 while(true)。

少一个关键字，少一套语法规则；do-while 的语义用 `for { ... if !cond { break } }` 两行就能表达，不值得为一个低频形态增加记忆负担。

**Q：什么时候用无表达式 switch 而不是 if-else 链？**
A：判定条件超过两个、且都属于同一主题时用 switch：case 对齐排版让"判定树"结构可见，命中即短路也避免 if-else 链里嵌套的 else 心智负担。只有一两个条件、或条件之间没有并列关系时，if 更自然。

**Q：带初始化语句的 if 到底好在哪？**
A：它把"算出一个中间值"和"用这个值判定"绑在同一个语句里，变量的作用域被编译器强制限制在 if/else 内。好处是读到 if 之外时可以确定 `r` 已死，不会在 50 行之后被误用——这是 Go 用作用域规则替代"变量该在哪声明"的口头约定。

**Q：`i%15==0` 换成先判 `%3` 再判 `%15` 能补救吗？**
A：只能在 case 里再嵌套判断，可读性更差。正确做法就是利用 switch 自上而下短路的性质，把最特殊的条件放最前——这也是无表达式 switch 表达"优先级判定"的天然优势。
